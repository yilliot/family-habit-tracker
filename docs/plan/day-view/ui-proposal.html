Habits by person, by day UI proposal · 9 Nov 2026 · traced from code on main + production data

Open the app, see your own today, tick.

Right now nobody in the family can tick anything: the last four-week sprint ended on 31 October and the app waits for a family meeting to start the next one. That has happened four times since April, and each time ticking stopped. This proposal removes sprints. Each person has their own page that opens on today. Anyone can add a habit whenever they like, and every tick since April stays in the history.

Notes

  1. Nothing can be ticked after a sprint ends. A tick outside the sprint's dates is refused (internal/service/ticks.go:66), and the home page only ever shows the active sprint (internal/service/queries.go:237). Sprint 5 ran 29 Sep–31 Oct, and its status is still “active”.
  2. The gaps between sprints add up: 15–20 Jun, 20–26 Jul, 25 Aug–28 Sep and 1 Nov until today. That is 57 days since April when nobody could tick anything.
  3. Habits are re-created for every sprint (internal/service/sprints.go:188). 爸爸's “带敬拜” exists five times. There are 76 habit rows for 21 habits.
  4. Every tap rebuilds the whole four-person, 33-day grid (internal/web/mutations.go:70), and the home page is 356 KB of HTML (measured on the live site).
  5. On a phone the grid scrolls sideways inside the page, and the progress cards overflow at 390 px.
  6. Four web fonts, two of them full Chinese families (internal/web/views/layout.templ:19); the phone already has good Chinese fonts of its own.
  7. Adding a habit needs a running sprint (internal/service/habits.go:22). Between sprints, nobody can even add one.

Notes

  1. The names at the top switch person in one tap and show how far each person is today (“3 / 8”). A name turns green when that person has done everything.
  2. Points and goal: the same numbers the grid shows now, read from all of the person's history. The “− deduct” dialog is the one already in use (internal/web/views/components.templ:54).
  3. “n days running” appears from 2 days up. Habits with the same name are counted as one, so 可遇's piano streak runs back past the old sprint's end.
  4. Adding a habit: type a name, tap Add. It shows from today, for this person only. No sprint and no settings page are needed.
  5. Today and the 6 days before it can be ticked; a day further back opens read-only. Days in the future cannot be opened (the › arrow stops at today).
  6. History is untouched: an old day lists the habits that person had on that day, with the ticks exactly as recorded. 12 Aug is real data.
  7. A tap still flips the box at once and is saved in the background. If saving fails, it flips back with a message, as it does now (internal/web/static/app.js:68).

Notes

  1. Renaming fixes a name (“分种” → “分钟”) and keeps every tick. Reordering moves a habit up or down the person's day.
  2. Stopping takes the habit off the list from tomorrow (or from today, if it has no tick today). A habit added by mistake today, with no ticks, is simply removed.
  3. Restart brings a stopped habit back from today. Because it has the same name, its history and streaks continue as one line.
  4. Goal rules are the existing ones (internal/service/rewards.go): one goal at a time, a goal you can already afford is reached at once, and a reached goal's cost is frozen. Only where they live changes.
  5. Archiving a person keeps their enrolment and ticks, as now (internal/service/people.go:73).

Build notes

Same Go binary, same SQLite file, same Axon service. It is built here and deployed with make deploy, which takes a checked snapshot of the database before it swaps the binary (deploy/install.sh:28).

What happens to the data, once, at first start

RecordChangeWhy it is safe
Habits (76)Each one gets its owner and the days it ran. The 21 habits from the last sprint keep running with no end date; older ones end on their sprint's last day.Columns are only added and filled in. No tick moves: the 450 ticks stay on the habits they were made on.
Deductions (2)Each one gets its owner.The amounts and reasons are untouched.
PointsRead from each person's whole history instead of “this sprint”.Checked against production: 爸爸 115, 妈妈 7, 可遇 122 and 奇乐 0, the same both ways.

Reused as is

  • A tick can never be counted twice (unique habit + day, internal/db/schema.sql:89); a tap flips at once and rolls back on failure (internal/web/static/app.js:70–113).
  • Goal rules and the celebration (internal/service/rewards.go, internal/web/views/components.templ:92), the deduct dialog (components.templ:54).
  • Daily snapshots, health check and deploy (internal/backup, internal/web/server.go:137, deploy/).
  • Everything still works without JavaScript; every box is a real form.

Faster

  • One person and one day per page: about 20 KB instead of 356 KB. A tap answers with that one row and the points card, not the whole grid.
  • Chinese text uses the device's own fonts (PingFang or Noto). Only the Latin serif and Inter still load from Google.
  • CSS and JS carry a version in their URL and are cached for a year; a deploy changes the URL.
  • One index on each habit's owner keeps every page at a few indexed queries for decades of history.
